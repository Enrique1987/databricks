# Contributing

Thanks for helping improve this Databricks learning and architecture repository.

## Before opening a change

1. Read the [content standard](docs/quality/content-standard.md).
2. Use current Databricks terminology and cite primary sources.
3. Keep credentials, customer data, course exports, exam dumps, generated outputs, and large binaries out of Git.
4. Prefer a small, reviewable change with a clear validation method.

## Pull requests

Describe the problem, the change, how it was validated, and any limitations. For product behavior, link to the official documentation or release note used during review.
