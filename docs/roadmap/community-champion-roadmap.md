# Databricks Community Champion Roadmap

Last reviewed: 2026-08-16

## Goal

Build a public body of work that consistently helps Databricks practitioners solve real problems.

Databricks describes Community Champions as people who repeatedly share expertise, support other practitioners, and strengthen the community through answers, articles, videos, and events. This is different from passing a certification: certifications validate knowledge at a point in time, while Community Champion recognition is based on visible, sustained contribution.

There is no public deterministic checklist that guarantees recognition. This roadmap therefore treats the official Community Champion descriptions as signals, not as admission criteria.

## Evidence portfolio

| Signal | Evidence to publish | Quality bar |
| --- | --- | --- |
| Practical expertise | Reproducible Databricks projects | Setup, tests, cost notes, teardown, and official sources |
| Community support | Helpful answers in Databricks Community | Reproducible explanation, source link, and follow-up |
| Knowledge sharing | Technical articles, talks, or short videos | Original content with a real problem and measured result |
| Consistency | Monthly contribution log | Steady cadence rather than a one-time content burst |
| Collaboration | Reviews, issues, and open-source contributions | Constructive, technically specific participation |

## 90-day plan

### Days 1-30: establish credibility

- Complete the repository quality baseline: reviewed sources, clear ownership, no course exports, no exam dumps, and no secrets.
- Publish one small production-style project using Declarative Automation Bundles, tests, and separate development and production targets.
- Write one technical article from that project and answer at least four community questions with tested examples.
- Create a public contribution log in this repository.

### Days 31-60: demonstrate depth

- Publish a streaming or CDC project using Lakeflow Spark Declarative Pipelines.
- Include Unity Catalog governance, data-quality expectations, observability, failure recovery, and cost trade-offs.
- Publish a second article and one architecture decision record.
- Contribute a documentation correction, reproducible issue, or pull request to a relevant open-source project.

### Days 61-90: demonstrate leadership

- Publish an AI or ML project with evaluation, governance, deployment, and monitoring.
- Deliver a meetup session, webinar, or recorded walkthrough.
- Turn repeated community questions into a concise troubleshooting guide.
- Review the portfolio against the evidence table and ask experienced community members for specific feedback.

## Project backlog

1. **Production ingestion reference** — Auto Loader or Lakeflow Connect, schema evolution, quarantine, replay, and operational metrics.
2. **CDC pipeline** — streaming tables, materialized views, expectations, late data, recovery, and change propagation.
3. **Governed data product** — Unity Catalog permissions, row filters, column masks, lineage, and OpenSharing.
4. **Declarative deployment** — bundle targets, CI checks, integration tests, promotion, and rollback.
5. **AI agent or RAG system** — AI Search, evaluation, tracing, governance, serving, monitoring, and cost/quality trade-offs.

Each project must contain a problem statement, architecture decision, runnable code, automated checks, operational guidance, limitations, and a teardown path.

## Certification track

Certifications support the goal but do not replace public contribution. Prioritize hands-on proof in this order:

1. Data Engineer Associate fundamentals.
2. Data Engineer Professional production engineering: Python/SQL, streaming, Lakeflow pipelines, orchestration, CI/CD, Declarative Automation Bundles, governance, monitoring, and optimization.
3. Generative AI Engineer Associate for RAG, agents, evaluation, governance, deployment, and monitoring.
4. Machine Learning Professional when the portfolio includes production ML lifecycle work.

Always download the latest exam guide shortly before booking an exam. Databricks updates objectives and product names over time.
